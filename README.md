# campus-doc · 캠퍼스 문서

한글 문서의 서식을 재사용 가능한 컴포넌트로 관리하고, 자연어 대화로 양식을 만들거나 내용을 수정하는 문서 스킬입니다.
운영계획서·결과보고서처럼 표지, 번호 제목, 불렛, 일정표, 예산표가 반복되는 문서를 대상으로 합니다.
대학·전문대학뿐 아니라 비슷한 공문형 보고서를 쓰는 기관에서도 자기 양식을 등록해 사용할 수 있습니다.

**현재 버전: 0.1.1 · 실행 가능한 프로토타입.** Windows 폴더 내부 자동 셋업과 실제 파일 생성·수정은 검사했습니다.
Gemini 앱에서 링크 한 개로 준비부터 파일 반환까지 끝나는 과정과 한컴에서의 최종 화면 비교는 아직 검증하지 않았습니다.

가능하면 설치 안내에 따라 준비하고, 예시 양식 생성과 수정까지 검사해줘.
실행 도구가 없으면 지금 가능한 단계와 내가 해야 하는 최소 단계를 알려줘.

## 어떤 일을 할 수 있나요?

| 요청 | 동작 |
|---|---|
| “이 제목 모양으로 새 컴포넌트 추가해줘.” | 기존 요소 복제, 같은 서식의 XML 가져오기, 새 문단·글자 run 작성 |
| “이 제목 컴포넌트의 색과 글자 크기를 바꿔줘.” | 스타일을 분리하고 컴포넌트의 새 버전 저장 |
| “운영계획서와 결과보고서 예시 보여줘.” | 등록된 양식과 컴포넌트 목록 조회, 예시 파일 생성 |
| “표지, 목적, 일정표, 예산표 순서로 만들어줘.” | 컴포넌트 순서·페이지 구분·버전을 지정하고 HWPX 생성 |
| “이 문서의 프로그램명과 날짜를 수정해줘.” | 문서 내용만 바꾼 사본 생성 |
| “우리 기관 문서를 새 양식으로 등록해줘.” | 기존 양식 옆에 전용 폴더를 만들고 구조·스타일·내용 슬롯 추출 |
| “다음부터 우리 기관 양식으로 써줘.” | 중앙 목록에서 기관·부서·문서 종류에 맞는 추가 양식 선택 |

사용자는 JSON, 스타일 ID, 문단 번호를 작성할 필요가 없습니다. AI가 자연어 요구사항을 내부 입력으로 바꾸고 도구를 실행합니다.
스크립트는 문서 처리 엔진이며, 자연어를 이해하는 모델은 사용자가 쓰는 AI입니다.

## 처음 문서를 만드는 대화

AI는 이미 받은 정보는 다시 묻지 않고, 필요한 항목을 순서대로 받습니다.

1. 기관명, 부서명, 기관 CI 파일
2. 첫 페이지 제목과 줄을 나눌 위치, 표지 날짜
3. 두 번째 페이지 제목
4. 목차 또는 본문 항목과 순서
5. 항목별 내용, 불렛 목록, 표의 값
6. 생성 파일과 검사 결과

예를 들어 다음처럼 시작합니다.

```text
기관은 예시대학교, 부서는 취업지원팀이야.
표지는 첫 줄 ‘2026학년도 취업지원 프로그램’, 다음 줄 ‘운영계획서’로 해줘.
두 번째 페이지 제목은 ‘취업지원 프로그램 운영계획’.
목적, 개요, 일정, 예산 순서로 만들고, 내용은 항목별로 물어봐.
```

임의 CI 삽입, 긴 표지 제목의 줄 나눔, 임의 목차의 조판은 해당 컴포넌트와 이미지 자원을 실제로 구성하고 확인해야 합니다.
공개 예시의 CI는 중립 이미지로 바꿨으며, 그림 개체 3개의 위치·크기·정렬·여백 정의는 참조 양식과 동일합니다.
새 기관 CI의 가로세로 비율을 자동으로 맞추는 기능은 아직 별도 구현이 필요합니다.
위 입력 흐름이 있다는 이유로 모든 디자인 조합이 자동 지원된다고 판단하지 않습니다.
자세한 대화 계약은 [자연어 작성 흐름](references/conversation.md)에 있습니다.

## 비개발자 Windows에서 준비하기

1. [최신 배포 ZIP](https://github.com/devlikebeaver/campus-doc/releases/latest) 또는 GitHub의 **Code → Download ZIP**으로 받습니다.
2. ZIP을 일반 폴더에 압축 해제합니다.
3. **SETUP.cmd**를 두 번 클릭합니다.
4. 완료되면 `runtime/samples/`에 만들어진 예시 문서를 확인합니다.

Windows 10/11 x64용입니다. 처음에는 인터넷이 필요합니다.
셋업은 Python·Node와 필요한 라이브러리를 **이 폴더의 `runtime/` 아래**에 준비합니다.
별도로 Python·Node를 설치하거나 관리자 권한을 사용할 필요가 없습니다. 시스템 PATH와 전역 Python 패키지는 변경하지 않습니다.

다운로드 파일은 저장된 SHA-256과 대조한 뒤 사용합니다.
설정 후 같은 폴더에서 다시 실행하면 다운로드 캐시를 재사용합니다.
기업 PC에서 다운로드나 실행이 차단되어 있으면 오류를 AI에게 전달하세요. 조직 정책을 우회하는 설치는 안내하지 않습니다.

SETUP.cmd가 성공해도 Gemini 채팅이 PC 폴더에 접근하거나 명령을 실행할 수 있게 되지는 않습니다.
AI가 사용자의 작업 폴더에 접근할 수 있는 환경인지 별도로 확인해야 합니다.

## 실행 가능한 에이전트에서 준비하기

Git이 있는 환경에서는 저장소를 가져옵니다.

```sh
git clone https://github.com/devlikebeaver/campus-doc.git
```

Windows 에이전트는 저장소 폴더에서 다음 명령을 실행합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/bootstrap.ps1
```

준비한 Python과 Node를 사용해 명령을 실행하는 도우미입니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 registry.py list
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 library.py catalog
```

Linux/macOS 또는 기존 Python 실행 환경에서는 다음을 사용합니다. Python 3.13을 기준으로 검사합니다.

```sh
python scripts/setup.py
python scripts/doctor.py
python scripts/smoke.py
```

이 경로는 기존 Python과 pip를 사용합니다. Node는 네이티브 HWP 바이너리 생성·고정 길이 수정에 필요합니다.
Node가 없더라도 HWPX 구성·편집은 별도로 사용할 수 있습니다. 유료 문서 API나 MCP 서버 등록은 기본 실행에 필요하지 않습니다.

## 문서를 만드는 디자인 시스템

기본 예시는 운영계획서 16개, 결과보고서 23개, 총 **39개 컴포넌트**입니다.
원본 문서와 실제 기관·사업·실적·예산 데이터는 공개 패키지에 포함하지 않습니다.
이미지는 새로 만든 CI 자리표시자로 바꿨으며 글꼴 파일은 배포하지 않습니다.

각 컬렉션은 다음을 따로 관리합니다.

| 파일 | 역할 |
|---|---|
| `manifest.json` | 컴포넌트 이름, 순서, 페이지 힌트, 표의 구조와 배치 |
| `tokens.json` | 글꼴 이름, 글자 크기, 자간, 장평, 색, 문단·테두리 정의 |
| `components/*.xml` | 표지·제목·본문·불렛·표의 실제 HWPX 구조 |
| `field-schema.json` | 각 내용 슬롯의 글자 스타일과 길이 기준 |
| `package-base.zip` | 본문과 분리된 글꼴·스타일 정의와 이미지 자원 |

같은 숫자의 스타일 ID라도 다른 컬렉션에서는 다른 서식입니다.
기관별 컬렉션을 섞을 때는 스타일과 이미지 자원을 가져오고 참조를 다시 연결해야 합니다. 이 일반적인 혼합 기능은 아직 완성되지 않았습니다.
`tokens.json`은 실제 서식의 목록이며, 모든 조판에 자동 적용되는 범용 CSS 엔진은 아닙니다.

불렛은 글꼴과 코드포인트를 함께 보존합니다.
예시의 Wingdings U+F06D를 임의의 `○`·`●`로 대체하지 않습니다.
첫 페이지는 제목의 글꼴·크기뿐 아니라 자간·장평·줄 위치·헤더·CI까지 따로 검사합니다.

## 중앙 양식 목록과 추가 양식

`scripts/registry.py list`가 `library/registry.json`을 만들고 갱신합니다.
중앙 파일에는 위치, 문서 종류, 기관·부서, 사용 여부, 우선순위, 검토 상태, 컴포넌트·양식 버전이 들어갑니다.
스킬은 문서 작업을 시작할 때 이 목록을 먼저 읽습니다.

```text
assets/
  plan/                     공개 운영계획서 예시
  report/                   공개 결과보고서 예시
  my-campus-plan/           사용자가 자기 문서에서 추출한 전용 양식
library/
  registry.json             로컬 중앙 목록
  components/               추가·수정한 컴포넌트 버전
  templates/                저장한 양식과 고정 버전
runtime/                    실행 환경, 생성 예시, 검사 결과
```

기본 검색 위치는 `assets/`이며, 유효한 manifest와 자원 ZIP을 가진 추가 폴더를 발견합니다.
사용자가 지정한 양식을 우선하고, 기관·부서·종류가 맞는 추가 양식을 기본 예시보다 우선합니다.
후보가 동순위이면 선택받습니다. 비활성·누락·구조 검사 실패 양식은 자동 선택하지 않습니다.

개인 양식 폴더, 로컬 중앙 목록, 사용자 컴포넌트와 생성 파일은 `.gitignore`로 공개 커밋 대상에서 제외합니다.
로컬 양식 관리에는 별도 중앙 서버가 필요하지 않습니다.
같은 드라이브의 경로는 상대 경로로 저장하며, 다른 드라이브의 외부 폴더는 절대 경로로 연결합니다.
자세한 구조는 [문서 추출·중앙 관리](references/registry-and-import.md)에 있습니다.

## 기존 문서에서 추출하고 반복 검토하기

에이전트는 다음 명령으로 새 전용 컬렉션을 만듭니다.

```sh
python scripts/import_document.py extract INPUT.hwp --name my-campus-plan --kind plan --institution 예시대학교 --department 취업지원팀
python scripts/import_document.py review assets/my-campus-plan
python scripts/import_document.py rebuild assets/my-campus-plan CHECK.hwpx
```

일반 문서는 최상위 문단별 후보부터 추출합니다. 이후 표지·제목·본문·표 등 의미 있는 묶음으로 그룹을 정합니다.
`--profile plan/report`는 **배포 예시와 문단 구조가 같은 문서용**입니다. 임의 공문에 무조건 적용하지 않습니다.
참조 PDF가 있으면 `--reference-pdf`로 함께 보관합니다.

검토 트리는 컴포넌트 → 도형·표 → 셀 → 문단 → 글자 run → 텍스트까지 내려갑니다.
매번 `reviews/iteration-NNNN.json`에 검토 기록을 남깁니다.
자동 검사는 스타일·이미지 참조, 병합 셀, 재구성 결과와 원본 해시를 확인합니다.
의미 있는 컴포넌트 경계와 화면상의 외형은 AI가 실제 자료를 보고 판단하고 수리해야 합니다.

큰 `component-tree.json` 전체를 매번 AI에게 넣지 않습니다. 필요한 컴포넌트와 자식 요소를 스크립트로 골라 읽습니다.
원본 사본과 개인 분석 기록은 사용자 작업 폴더에 보관합니다.

## 용량과 AI가 읽는 범위

0.1.1 기준 공개 소스는 압축 전 약 4MB, 배포 ZIP은 약 0.26MB입니다.
Windows 셋업 후 `runtime/`는 다운로드 캐시와 생성 예시를 포함해 이 시험 환경에서 약 142MB였습니다.
추가 기관 양식과 분석 기록을 보관하면 그만큼 늘어납니다.

전체 파일을 매 요청마다 모델에 넣지 않습니다. 스킬 지침, 중앙 목록에서 선택한 양식,
필요한 컴포넌트와 스타일만 읽고 큰 XML·JSON은 스크립트로 처리합니다.
실행 메모리와 Gemini에서의 응답 시간은 별도로 측정하지 않았습니다.

## 검증과 성공 기준

Windows 자동 셋업은 다음 조건을 확인한 뒤 완료를 보고합니다.

1. 고정 버전의 라이브러리를 실제로 import할 수 있음
2. 중앙 목록에서 기본 양식 두 개와 컴포넌트 39개를 확인함
3. 운영계획서·결과보고서 HWPX를 생성하고 ZIP·XML·스타일·표 병합을 검사함
4. HWPX 내용을 수정함
5. 합성 HWP 예시의 고정 길이 내용을 수정하고 비텍스트 레코드가 유지됨을 확인함

검사 결과는 `runtime/setup-status.json`, `runtime/smoke-result.json`에 남습니다.
더 넓은 회귀 검사는 다음과 같습니다.

```sh
python scripts/check.py
python scripts/check_library.py
python scripts/check_registry.py
```

컴포넌트 버전 고정, 스타일 수정의 분리, 개체 ID 중복 방지, 내용만 수정, 기존 자원 불변,
문서별 추출, 재귀 트리, 양식 자동 발견·선택, 다중 섹션 재구성을 검사합니다.

**구조 검사 통과는 한컴에서의 외형 일치 판정이 아닙니다.**
한컴에서 원본과 결과를 같은 환경으로 렌더링하고 각 페이지의 글꼴·자간·불렛·헤더·표를 비교해야 합니다.
글꼴 대체, 긴 내용의 재조판, 페이지 수 변화는 별도로 확인합니다.
검사 범위와 남은 항목은 [검증 기록](docs/verification.md)에 적습니다.

## 현재 제한

- 기본 공개 예시는 익명 HWPX 자원입니다. 사용자 원본의 네이티브 HWP 바이너리 조각은 배포하지 않습니다.
- 네이티브 HWP 고정 길이 편집은 UTF-16 길이가 같은 교체용입니다. 긴 내용은 HWPX 편집과 재조판 검사를 사용합니다.
- 새로운 컴포넌트 조합은 현재 단일 섹션 HWPX를 생성합니다. 다중 섹션 문서의 원형 추출·재구성은 지원합니다.
- 문서 간 스타일·이미지 자동 통합, 임의 CI 입력과 긴 표지 제목의 자동 조판은 추가 구현·검증이 필요합니다.
- 자동 구조 검토는 지원하며, 모든 의미·외형 결함을 자동으로 찾아 수리하는 루프는 완성되지 않았습니다.
- HWP→PPTX는 이 버전의 범위에 포함하지 않습니다.
- Gemini 앱에서 준비→생성→다운로드까지의 전체 사용 흐름은 아직 미검증입니다.
