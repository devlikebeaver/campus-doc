# 자연어 문서 작성 흐름

사용자는 JSON, 문단 번호, 글자 스타일 ID를 입력하지 않는다. 사용자와의 대화에서
문서 요구사항을 모으고, 에이전트가 `scripts/brief.py`의 구조로 정리한다.
이미 대화나 첨부파일에서 확인한 정보는 다시 묻지 않는다. 여러 항목을 한 문장으로
말한 경우 모두 반영한다. 사용자가 답을 바꾸면 해당 값만 갱신한다.

기관과 문서 종류가 확인되면 `registry-and-import.md`에 따라 중앙 레지스트리에서
추가 양식을 우선 조회한다. 같은 조건의 후보가 여럿이면 양식 이름으로 선택받는다.
사용자가 지정한 양식을 기본 예시로 되돌리지 않는다. 새 문서에서 추출해 등록하는
요청은 새 전용 컬렉션으로 진행하고, 다음 작업에서 그 목록을 재사용한다.

## 입력 순서

1. **기관 정보**: 기관명, 부서명, 사용할 CI 파일. 같은 기관으로 이어지는 작업에서는
   저장된 정보를 재사용한다. CI가 없으면 기관명 텍스트 헤더를 선택할 수 있다.
   파일을 요청해야 할 때는 일반 대화로 요청한다. 텍스트 입력 전용 질문 도구에
   파일 업로드 요청을 넣지 않는다.
2. **첫 페이지**: 표지 제목과 줄 나누기, 표지 날짜. 사용자에게 자연스럽게
   “첫 페이지 제목은 무엇으로 할까요? 줄을 나눌 위치도 알려주세요.”라고 묻는다.
   사용자가 줄을 지정하면 그대로 보관한다. 지정하지 않으면 문장 의미와 실제 글꼴
   폭으로 줄 나누기를 제안한다. 문자 수만으로 자르거나 임의로 자간을 늘리지 않는다.
3. **두 번째 페이지**: 본문 시작 제목. 표지와 같다고 하면 동일 값을 재사용하고
   다시 묻지 않는다. 표지와 다른 짧은 제목도 허용한다.
4. **목차/본문 구성**: “어떤 항목으로 구성할까요? 목적, 개요, 일정, 예산처럼
   순서대로 말씀해주세요.” 목차가 본문 섹션 순서를 뜻하는지 별도의 목차 페이지를
   뜻하는지도 문맥으로 판단한다. 불명확하면 이 차이만 짧게 확인한다.
5. **섹션별 내용**: 항목마다 본문, 불렛 목록, 표, 주석을 받는다. 사용자가 내용을
   통째로 주면 섹션에 배정한다. 실제 수치가 없으면 입력란으로 남긴다.
6. **생성과 검증**: 기관 정보, 제목 줄바꿈, 목차 순서를 짧게 보여준 뒤 생성한다.
   이것은 기본적인 내용 확인이지 별도의 승인 절차가 아니다. 이미 내용이 명확하면
   곧바로 생성한다. 불렛·글꼴·자간·헤더·표 스타일을 디자인 시스템에서 적용한다.

한 번에 하나의 단계에 집중하되 이미 받은 정보를 건너뛴다. 형식의 내부 구현은
사용자 입력 흐름에 노출하지 않는다. 날짜는 현재 날짜로 임의 확정하지 않는다.
현재 과제에서는 PPTX를 묻거나 생성하지 않는다.

## 내부 계약과 실제 구현 범위

`brief.py`는 대화에서 정리한 정보의 누락, 다음 질문, 구조화된 작성 요구사항을
관리한다. 이 도구 자체는 LLM도 문서 렌더러도 아니다. 자연어 이해와 질문은 Codex가
담당하고 문서 파일 생성은 별도 생성기가 담당한다.

요청이 새 컴포넌트나 양식 관리에 해당하면 `references/functions.md`의 다섯 기능과
`scripts/library.py`를 사용한다. 문서 내용 수정은 컴포넌트의 새 버전을 만들지 않는다.
컴포넌트 수정은 기존 문서에 자동으로 번지지 않는다. 양식은 사용하는 버전을 고정한다.

기존 `generate-hwp`는 추출된 고정 양식의 네이티브 HWP 컴포넌트 생성기다. 대화
요구사항의 임의 목차, 임의 CI, 긴 제목을 자동으로 지원한다고 말하지 않는다.
그 요구사항을 적용하려면 해당 컴포넌트·이미지·조판을 실제로 구성하고 렌더링하여
검증해야 한다. 대화 입력이 끝났다는 사실을 문서 생성 성공으로 보고하지 않는다.

특히 원본 PDF의 Wingdings U+F06D 불렛을 일반 `○`로 바꾸지 않는다. 표지에서
함초롬바탕으로 해석된 글꼴과 자간·장평을 모두 함께 검사한다.

## 입력 예시

사용자: “기관은 예시대학교, 부서는 대학일자리플러스센터. CI는 보낸 파일에 있고,
표지는 ‘2026학년도 취업지원 프로그램’ 다음 줄에 ‘운영계획서’. 두 번째 페이지는
‘취업지원 프로그램 운영계획’. 항목은 목적, 개요, 일정, 예산.”

기관/표지/본문 제목/섹션 순서를 한 번에 반영하고, CI가 실제 첨부에서 추출 가능한지
확인한다. 이미 지정된 제목을 다시 묻지 않고 목적에 넣을 내용부터 받는다.
